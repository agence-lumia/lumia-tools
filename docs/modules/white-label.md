# WhiteLabel module

`includes/Modules/WhiteLabel/` — `Module.php` and `MenuProfileManager.php`. Settings live under `lumia_module_white_label`.

Four concerns in a single module (all in `Module.php` except the menu profiles), each hooked only when its settings group is active:

- **Admin bar / footer**: each toggle of the `admin_bar`/`footer` settings conditionally registers its own `admin_bar_menu`/`admin_head`/`gettext`/`show_admin_bar` hook in `init()` — nothing is hooked until the matching setting is enabled.
- **Profile page cleanup** (`profile` settings): if a `profile.*` toggle is on, an `admin_head` hook (`clean_profile_page()`) injects CSS on `profile.php`/`user-edit.php` to hide the chosen core sections (color scheme, keyboard shortcuts, toolbar toggle, application passwords, language, bio, sessions, editor options). Visual hiding only — the features stay intact on the server side. It targets the stable classes of core's `<tr>`/sections rather than `remove_action` (registrations vary with the WP version).
- **Local avatars** (`avatars.local` setting): when active, a `get_avatar_data` filter (`apply_local_avatar()`) substitutes the image uploaded by the user; a media-picker field is rendered on the profile form via `personal_options` and saved in the `lumia_local_avatar` user meta (declared in `get_uninstall_keys()`). No avatar meta → WordPress falls back to Gravatar. The native "Profile Picture" row (Gravatar) is hidden by CSS via `admin_head`.
- **Menu profile storage** (`MenuProfileManager.php`): static CRUD/resolution layer, independent of the settings, stored under its own option `lumia_wl_menu_profiles` (not `lumia_module_white_label`). `get_active_for_user()` resolves the highest-priority active profile per user (include_users > include_roles > apply_to_all, exclusions always win, ties broken by `updated_at`) and caches the result in a per-user transient (`lumia_wl_menu_user_{gen}_{id}`, TTL 1 h). `{gen}` is a **generation** stored in the `lumia_wl_menu_cache_gen` option: `clear_all_cache()` increments it instead of looping over users (the old loop was capped at 500 accounts, beyond which the others kept a stale profile). Call `clear_user_cache()`/`clear_all_cache()` after any profile mutation. This class is consumed by the **MenuCreator** module, not by WhiteLabel's `Module.php`.

**"Howdy"**: removed by rewriting the `my-account` node on `admin_bar_menu` (the translated prefix of `Howdy, %s` is stripped from the title), not via `gettext`, which ran for every string of every page.
